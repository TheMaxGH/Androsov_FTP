# Production notes

## Как понять, что сервер запущен

В GUI вкладка **Серверы** показывает:

- цветной статус профиля: `Остановлен`, `Запускается`, `Запущен`, `Ошибка`;
- адрес сервера, например `ftp://192.168.1.178:2121`;
- uptime;
- число активных сессий;
- ошибку порта или TLS, если запуск не удался.

Кнопка **Запустить** активна только когда выбранный сервер остановлен. Кнопка **Остановить** активна только когда сервер запущен.

## Если IP/порт уже занят

Один TCP endpoint может слушать только один процесс. Если `0.0.0.0:2121` или `192.168.1.178:2121` уже занят, второй сервер на том же endpoint не запустится.

Что делать:

- остановить старый процесс;
- выбрать другой порт, например `2122`;
- привязать сервер к другому IP, если у машины несколько сетевых интерфейсов.

## Несколько серверов

GUI поддерживает несколько профилей. Каждый профиль можно запустить отдельно, если у него уникальная пара `host:port`.

Пример:

- `Public`: `0.0.0.0:2121`, anonymous read-only;
- `Private`: `0.0.0.0:2122`, только авторизованные пользователи;
- `Admin`: `127.0.0.1:2123`, локальный сервисный FTP.

## Пользователи и anonymous

Для каждого сервера можно добавить несколько пользователей:

- логин;
- пароль;
- индивидуальная папка или общая папка сервера;
- права `Чтение и запись` или `Только чтение`;
- флаг включения.

Anonymous включается отдельно и всегда получает только read-only права `elr`.

## FTPS

Обычный FTP удобен для учебного LAN-сценария, но не шифрует логин и пароль. Для production включайте `ftps`, указывайте сертификат и ключ.

CLI:

```powershell
python main.py --legacy-server --tls --certfile cert.pem --keyfile key.pem --root "D:\Share"
```

Для FTPS требуется `pyOpenSSL`.

## Firewall и passive range

Для доступа с другой машины нужно открыть:

- основной TCP-порт сервера, например `2121`;
- passive range, например `60000-60100`.

UPnP может пробросить основной порт, если роутер это поддерживает. Для надежного production лучше настроить firewall/NAT вручную.

## Лимиты

В профиле сервера доступны:

- максимум соединений;
- максимум соединений на IP;
- лимит upload/download в KB/s;
- IP allow/deny list.

## Рекомендации безопасности

- Не публикуйте обычный FTP в интернет без FTPS.
- Не храните реальные пароли в публичном репозитории.
- Ограничивайте root-папку только нужной директорией.
- Используйте read-only права там, где запись не нужна.
- Включайте deny list для подозрительных адресов.
